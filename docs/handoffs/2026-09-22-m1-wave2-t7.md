## What was built

- `pipeline/metadata_loader.py` — `load_experiments(conninfo, path=EXPERIMENTS_PATH)`:
  one transaction, `SET LOCAL app.actor = 'loader'`, then an `INSERT ... ON CONFLICT
  (experiment_id) DO UPDATE` per experiment with one `CASE WHEN is_manual(...)` guard per
  correctable column, transcribed from ADR-0012's SQL rather than re-derived. Structural
  columns (`start_time`, `end_time`, `duration_s`) are always overwritten from the file;
  no hard deletes anywhere. `CORRECTABLE_COLUMNS` maps the JSON's key spelling
  (`current_setpoint_nominal_A`, `solvent_flow_nominal_Lmin`) to the table's
  lowercase-folded columns — the one place that mapping is spelled out.
- `scripts/load_experiments.py` — CLI entrypoint, reusing `scripts.migrate`'s
  `load_env`/`connect_kwargs` rather than duplicating `.env` parsing.
- `tests/integration/test_metadata_loader.py` — 9 tests, `postgres`-marked, throwaway
  schema per test (T6's pattern, not a throwaway database — `CREATE SCHEMA`/`DROP SCHEMA
  ... CASCADE`, teardown in the fixture's `finally`).

## Findings

1. **The first load never produces a provenance row for any field.** The trigger is
   `AFTER UPDATE`, not `AFTER INSERT` (migration 0002, by design), so
   `experiment_field_source` is empty until something actually changes on a *second* run.
   `test_loader_owned_field_change_is_recorded_as_loader` exercises this deliberately: it
   loads once, edits a copy of `experiments.json`, and reloads to see a `loader`-sourced
   provenance row appear for the first time. Nothing here contradicts ADR-0012 — it says
   the trigger is `AFTER UPDATE` — but it wasn't spelled out as a consequence anywhere,
   and it's the reason the first test in the file only asserts on `experiment`, not on
   `experiment_field_source`.
2. **psycopg3 timestamp handling** — `start_time`/`end_time` are converted with
   `datetime.fromisoformat(...)` in Python before binding, rather than passing the JSON's
   `"...Z"` strings straight through and relying on an implicit text→timestamptz
   assignment cast. Both would likely work; the explicit conversion was chosen so the
   adapted type is unambiguous rather than inferred from context.
