## What was built

- `migrations/0001_experiment_table.sql` — the `experiment` table. Structural identity
  columns (`experiment_id`, `start_time`, `end_time`, `duration_s`) are `NOT NULL`; the
  six columns ADR-0012's provenance trigger protects (`operator`, `sorbent_batch`,
  `notes`, and the three nominal parameters) are nullable, per the plan's own wording
  ("nullable operator, sorbent_batch, notes and the nominal parameters") even though
  only three are actually null in the current `experiments.json`.
- `migrations/0002_experiment_provenance.sql` — `field_source` enum,
  `experiment_field_source`, `is_manual()`, `record_experiment_provenance()` and the
  `experiment_provenance` trigger, transcribed verbatim from ADR-0012 rather than
  re-derived.
- `pipeline/pg_migrate.py` — the runner. `discover_migrations()` parses each filename's
  numeric prefix and sorts on the **int**, not the filename string or directory order.
  `run_migrations(conninfo, directory=...)` opens its own connection (autocommit),
  takes a **non-blocking** `pg_try_advisory_lock` (fails immediately with a named
  `RuntimeError` if another runner holds it, rather than waiting), records a SHA-256
  checksum per applied version in a `schema_migrations` table it creates itself, refuses
  to continue if an already-applied file's checksum has changed, and applies each
  not-yet-applied migration inside its own `conn.transaction()`.
- `scripts/migrate.py` — CLI entrypoint, same `.env`-loading convention as
  `scripts/init_influx.py`. Invoked as `python -m scripts.migrate` (see Finding 1).
- `tests/integration/test_migrations.py` — five `postgres`-marked tests, each against a
  throwaway **schema** (not database — see Finding 2), teardown in a `finally`-block
  fixture so it drops even on failure.

## Findings

1. **`python scripts/migrate.py` (bare path) does not work — `python -m scripts.migrate`
   does.** `scripts/pre_ingest_census.py`'s own docstring already documents this
   (`Run: python -m scripts.pre_ingest_census`), but the M0/M1 docs never surfaced it and
   `README.md`'s quick-start only lists the two scripts that don't import from
   `pipeline/` (`bootstrap_influx_token.py`, `init_influx.py`), so it reads as if bare
   invocation is the convention. It isn't, for any script that imports `pipeline.*`: `-m`
   puts the repo root on `sys.path`, bare-path invocation doesn't. `scripts/migrate.py`
   is written and documented against `-m`; the plan's V10 wording ("`python
   scripts/migrate.py` applies every migration") is read here as shorthand for "the
   script", not a literal invocation instruction — worth a line in `README.md`'s
   quick-start or a `MISTAKES.md` entry so the next script that imports `pipeline` doesn't
   silently reintroduce the same trap.
2. **Postgres can't give a per-test throwaway database the way T5 got one from
   InfluxDB** — `CREATE DATABASE` can't run inside a transaction. Used a throwaway
   **schema** instead (`CREATE SCHEMA` / `DROP SCHEMA ... CASCADE`, both transactional),
   with the runner's own connection scoped to it via the `options=-c search_path=...`
   libpq parameter. Same isolation property T5 established (start from nothing, drop
   even on failure), different Postgres-shaped mechanism — flagging in case this is the
   pattern T7's tests want to reuse rather than re-deriving.
3. **The `dac-postgres` named volume predated today's session** (created 2026-09-07,
   holding whatever `POSTGRES_PASSWORD` was in `.env` back then) and rejected the
   password currently in `.env` once the container was recreated — Postgres only applies
   `POSTGRES_PASSWORD` on first init of an empty data directory. No schema had ever been
   written to it (T6 is the first thing to touch Postgres schema at all), so the volume
   was dropped and recreated clean rather than recovering the old password — confirmed
   with Sebastian before doing it since it's a destructive action, even though nothing
   of value was in it. Doesn't contradict any ADR; purely a local-environment quirk from
   the gap between when T2 stood up the compose file and today.
