## What was built

- `tests/integration/test_retention.py` — one test, `influx`-marked. Creates a throwaway
  database with a **1-hour** retention period, writes one point 2 hours old and one 5
  minutes old, queries both back, asserts only the fresh one survives. Confirmed live
  against `influxdb:3.11.2-core`: the expired point is invisible **immediately** at query
  time — no polling/sleep needed, matching `ROADMAP.md`'s note that Core filters expired
  points at query time rather than on a delayed sweep.
- `tests/integration/test_raw_preservation.py` — two tests, `influx`-marked. Writes a
  high-precision negative float into `readings_numeric` and both categorical signals
  (`process_state`, `valve_state`) as literal strings into `readings_state`, reads back,
  asserts exact round-trip. The state test explicitly asserts the returned values are
  Python `str`, not int — the case ADR-0006 rejected integer-encoding to avoid.
- Both files create a **throwaway database per test** (not `dac_raw`), created and
  dropped via a `finally`-block fixture so teardown runs even on failure — same pattern
  as the fixture, mirrored across both files rather than factored into `conftest.py`
  (T2's file; T5 doesn't own it per the plan's per-task file ownership).

## Findings

1. **Database deletion works over plain HTTP, not just the CLI.**
   `DELETE /api/v3/configure/database?db=<name>` returns HTTP 200 and actually removes
   the database (verified: the name disappears from a subsequent
   `GET .../database?format=json`); deleting an already-gone name returns a plain 404,
   handled as a no-op by the teardown helper. The spike (`docs/spikes/U-13...md`) only
   exercised `influxdb3 delete database -y` via `docker exec`, and T4's handoff used
   delete without stating the mechanism. This closes that gap: no CLI shell-out is
   needed anywhere in this project's Python for database lifecycle management, keeping
   `init_influx.py`'s "HTTP path, not the CLI" property (standing assumption 2) true for
   teardown too, not just creation. Additive, doesn't contradict anything.
2. **`retention_period: "1h"` is accepted by the server** (confirmed via a direct probe
   before writing the test) — `parse_duration`'s unit-test coverage only proves the local
   parser accepts `1h`; this is the first place anything in the repo has actually sent
   `1h` to Core and gotten a 200 back.
